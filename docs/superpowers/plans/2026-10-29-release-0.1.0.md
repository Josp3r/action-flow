# ActionFlow 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish Core, Scenario and DevTools as public npm packages at version 0.1.0, then verify registry consumers.

**Architecture:** Preserve the implemented APIs and dependency graph. Changesets generates the initial versions and changelogs; pnpm packs workspace dependencies into installable tarballs. Publish the verified tarballs in dependency order.

**Tech Stack:** pnpm 10.34.5, Changesets 3, Node 22/24, npm registry.

**Spec:** User approval in this conversation: all three packages start at 0.1.0; publishing is authorized. Back up both npm profiles outside the repository with private permissions.

## Global Constraints

- Packages: @action-flow/core, @action-flow/scenario, @action-flow/devtools.
- Version 0.1.0, access public, dist-tag latest, registry https://registry.npmjs.org/.
- Preserve ESM exports and existing runtime APIs; no Plugin or intercept API additions.
- Credentials and npm profile backups stay outside Git; never print their contents.
- Use the existing clean checkout and standing commit/push authorization.

## Review Focus

- Published workspace dependencies must contain real 0.1.0 versions.
- A failed or partially successful publish must not trigger a blind version bump or overwrite.
- Scoped packages must be public and target the community registry.
- npm credentials, local configuration and test fixtures must not enter tarballs.
- Documentation must distinguish pre-publish preparation from verified registry availability.
